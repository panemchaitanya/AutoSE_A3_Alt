# ADR-017: Durable preparation-role conversations after provider interruptions

## Status

Accepted, 24 November 2026, after the submission deadline. Supersedes ADR-004 only for preparation-role conversation recovery; branch state and stage checks remain unchanged.

## Context

Corrected requirements runs repeatedly received one or two real model replies before HTTP 503 failures. Resume retained branch files but started the role conversation again. This discarded useful observations and repeated setup/read actions. The issue is separate from provider availability and does not make failed stages pass.

## Decision

Persist exact SpecWriter and Designer model conversation, tool observations, action index and next step before each model call. Reuse only when role, requested model, full system prompt/skill, task, extra context, step limit, harness source and TinyDB Python source fingerprint match. A changed contract/task/source invalidates the checkpoint. Completed finish results remove it. The total step cap survives interrupted attempts.

Do not checkpoint Reviewer conversations: its context must stay fresh. Do not add developer/tester shell replay. Stage checks and semantic judges still execute normally, and no checkpoint sets a stage to passed. Failed model calls are not successful usage.

## Alternatives

- Restart every conversation: simple but repeats successful preparation under intermittent outages.
- Summarize prior reasoning: lossy and risks changing the full A1 contract.
- Continue every role automatically: raises source/context and repeat-side-effect risk, particularly for implementation and review.

## Consequences

A future provider recovery can continue preparation after its last completed observation rather than repeating all setup. Checkpoints contain model reasoning and must stay excluded from reviewer context. Existing corrected-context exclusion of `.autose/` covers them. Model requests remain serial, bounded and free-tier only.

Offline tests simulate an interrupted call followed by recovery, task invalidation, reviewer non-persistence and cross-restart step caps. Seventeen harness tests and 245 combined baseline/harness tests pass locally. These stubs do not establish provider recovery, corrected A1 success or an end-to-end issue outcome. A process kill during a tool action may occur before its observation checkpoint; automatic replay of arbitrary shell effects is not guaranteed safe. This prototype is not a hostile-code sandbox.
