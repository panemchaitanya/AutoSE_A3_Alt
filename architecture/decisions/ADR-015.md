# ADR-015: Compact A1 adaptation for requirements calls

- Status: Rejected before any requirements call used it
- Decision areas: D3, D9
- Amends: ADR014 request-size recovery

## Context

The first four actual A3 attempts failed at requirements with provider503.
One fourth-attempt response wrote a spec before subsequent failure. The
full A1 skill adds about20KB to every call. Earlier short schema probes
answered quickly. Context size is a hypothesis, not a proven cause.

## Decision

Preserve the full A1 skill source, but load a separately named compact
pipeline adaptation. It keeps source/basis/readiness, ambiguity/conflict,
traceability and testability principles. It uses the assignment's single
spec.md output rather than all three A1 artifacts, and explicitly does not
claim full A1 workflow compliance or MCP support. No test or stage gate is
removed. Later results must name this changed prompt revision.

## Alternatives

Identical retries have repeatedly failed. Removing semantic checks would
violate the brief. Replacing A1 silently would erase provenance. Paid
fallback is not authorized and has not been shown to fix503.

## Consequences

Smaller requests may help availability, or may not. Summarization can lose
instruction detail; the full original remains inspectable. This changes
the prompt, so earlier/later runs are not a controlled model comparison.
Hidden tests remain sealed. A completed independent trial is still needed.

## Compliance correction,21:56 IST

The compact adaptation omitted mandatory A1 outputs and validation. It was
not merely a packaging change. Full-skill loading is restored, and the role
prompt now explicitly requires A1 SRS/REGISTER/VALIDATION plus spec.md as a
handoff summary. No requirements call used the compact adaptation: the
only resumed issue already had a passed requirements checkpoint. Earlier
runs used the full skill but a conflicting single-output role prompt, so
full A1 compliance of those artifacts is not established. Preserve this
limitation; do not infer compliance from stage testability alone.

Correction enforcement: versioned A1 output structural checks reject absent
sections/results; a separate semantic judge audits traceability, basis,
readiness and substantive validation. This is still fallible, not proof.
A new verification marker is required to skip requirements, and dependent
checkpoints are invalidated when the corrected contract is first applied.
Historical achieved-stage results remain historical, not current compliance.
