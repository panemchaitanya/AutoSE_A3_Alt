# ADR-019: Give requirements and its correction a bounded execution window

## Status
Accepted for late recovery work on 24 November 2026.

## Context
A3 run 45289772983 resumed SpecWriter at step 11, wrote three artifacts,
and reached finish at step 15. Structural validation correctly rejected
missing SRS and validation topics. The 30-minute job limit then killed
the correction attempt. This was not a passed requirements stage.
The provider retry policy can consume minutes per call during outages.

## Decision
Raise only the requirements job timeout from 30 to 90 minutes. Keep
40 agent steps, two requirements attempts, token limits, semantic checks,
and all downstream limits unchanged. Persisted correction recovery is a
separate requirement, not supplied by a longer timeout. Do not cancel a
working stage merely because it is slow. No success is inferred from time.

## Consequences
This gives one substantive attempt plus correction more room under the
observed provider delays. It is not a guarantee: 40 worst-case calls can
still exceed this bound. Longer jobs consume more runner time; the 90-minute
limit prevents an unbounded wait. Serial provider execution remains in force.
